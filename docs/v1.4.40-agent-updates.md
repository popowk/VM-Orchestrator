# Guest Agent v2.0.22 自动更新

宿主机 v1.4.40 启动后，通过现有的 HTTPS/WSS 来判断 VM 中已注册 Agent 上报的版本。检测到已连接 Agent 为旧版且没有正在执行或等待执行的远程运维/软件更新任务时，自动排队生成带 SHA-256 摘要的 VM 专属 Agent ZIP。Guest 使用已注册凭据与专属 CA 从 8766 下载，校验后独立升级进程安装。无需给客户虚拟机配置 GitHub Token、开放额外端口或安装额外计划任务。

- **默认自动更新：开启**；宿主机设置环境变量 `VMO_GUEST_AGENT_AUTO_UPDATE=0` 可关闭。旧版 Agent 必须能成功建立 WSS 才能自动升级。
- **更新限速**：同 VM/同版本两次尝试间隔至少 90 分钟，每 24 小时不超过 3 次；手动升级不受限，但会推迟自动重试。
- **不抢运行任务**：存在 QUEUED/CLAIMED/RUNNING 的远程运维或软件更新任务则本轮不派发；下一次 WSS 心跳继续检查。
- **结果核验**：后台 `远程运维→Guest Agent` 或 `GET /api/vms/{vm_id}/agent-upgrade` 查看已安装版本、打包版本及最后一次升级；不以已派发/启动作为升级成功依据，必须收到新版本心跳。
- **错误修复**：原 `ValueError (internal error)` 是错误类型被过度隐藏，并不等于 TLS 失败。现在按阶段记录 `CONFIG_JSON_INVALID`、`ENROLLMENT_PENDING_OR_INVALID`、`INVALID_HTTPS_GATEWAY`、`INVALID_REMOTE_MESSAGE` 等固定代码。`ConnectionResetError (10054)` 与 `TimeoutError` 在重连成功后属于可恢复链路故障。
- **安全注意**：升级包必须由受信任宿主机 v1.4.40 构建。不允许任意公开下载 URL、降级或覆盖 `state/agent.json`、`ca.pem`、持久化结果队列。不要把 8765 管理端开放给客户网络。

生产部署前在一个备份的 Windows VMware 客户机进行一次完整升级、回滚演练。
