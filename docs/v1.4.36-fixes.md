# v1.4.36 重点修复与升级说明

基于 v1.4.35（精简稳定版）制作。正式包中无测试代码/数据库/pyc。

## 1. 客户端「重装系统」模板失效

原商品首次开通的黄金模板若仍已封存且 VMX 文件存在，则优先保持原模板。
原模板已归档、删除或文件不存在时，仅可选该客户同一商品的**当前已封存且 VMX 存在**的模板；不得跨套餐自动选用其他模板。回退写入 `REINSTALL_TEMPLATE_FALLBACK` 审计。
无合法模板则返回 409，管理员需检查「商品与模板」映射。

## 2. A prior operation is still running or needs administrator review

这是任务幂等锁，而不是凭空报错。旧版在 Guest 断线后可能没有主动回收底层队列状态。
新版本按结果分类：

- Host 命令 **QUEUED 且 TTL 已过**：确认从未被 Guest 接收后，自动标为失败并解除阻塞。
- 软件更新 **QUEUED 超过 20 分钟且从未领取**：在 DB 中原子标为 `CANCELLED`，不会晚些时候自动安装；解除阻塞。
- 已领取、运行中但超时/失联：转为 `UNKNOWN` 或 `TIMED_OUT`，不自动重试，不自动解除；必须人工复核。
- Host 命令成功/明确失败：自动释放业务层锁；已获确认启动 PID 的后台命令只表示启动受理。
- 管理后台优先展示需要审核的任务，即使任务已过较长时间也能找到。

### 已经卡住的旧任务怎么处理？

先升级并重新启动单进程 Host 服务，打开客户端页面并刷新执行记录，或进入管理后台「思博客户服务 → 客户自助」。
如果显示「结果未知/超时待核对」，先检查该 VM 的 Windows 进程、更新包是否已安装、Guest Agent 日志、是否仍有进行中的命令/更新；确认后点击「核对后解除阻塞」。该操作**只解除业务层提交限制，不会重试也不会停止正在执行的 Windows 命令**。
若仍显示执行中，说明后台认为实际任务尚未结束；不要通过删库或强制改状态绕过。Host 命令超时约 6 分钟，软件更新在失去进度后最长 90 分钟转审核。

## 3. UI 布局

- 管理后台「客户自助」改为操作列表、操作配置、客户任务记录三块，带搜索、启停状态、编辑和审核。
- 客户页面主区域扩大至 1440px，操作选择框和执行按钮最低 48px，重要弹窗宽度提升。
- 客户遇到待确认的旧任务时明确显示原因并禁用重复提交，确认后自动恢复。

## 4. 生产升级步骤

1. 备份当前整个安装目录（尤其 `data/`）、DPAPI 密钥、Guest TLS 证书以及客户 VM。
2. 退出旧版 8765 和 8766，不要在进程运行时覆盖。
3. 把 v1.4.36 ZIP 解压到**与正式安装位置不同的路径**；运行 `Install-All.cmd`，随后运行 `Start-VM-Orchestrator.cmd`。
4. 登录并强制刷新浏览器（Ctrl+Shift+R），确认 `/ui/admin.js?v=1.4.36` 正常加载。
5. 用可丢弃的测试 VM 验证客户模板重装与 Guest WSS 自助任务，在生产机器上核对回退审计记录。

保持管理端 8765 与 Guest 8766 的访问隔离，不要公开管理员 API。

## 5. 验证范围

- Python 编译和 JS 语法检查
- 同商品模板回退：原模板有效、归档、文件缺失、替代模板未封存、跨商品禁止、审计
- 自助任务九组开发回归：未投递命令、失联命令、实时运行、正常完成、结果不确定的软件更新、未领取的软件更新、并发争用、Guest 失联更新、后台确认防护
- Chromium 离线浏览器交互：后台搜索/编辑/核对、客户端布局和解锁联动
