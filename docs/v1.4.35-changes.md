# VM Orchestrator v1.4.35 问题修复、目录精简与验证说明

**基线**：上传的 v1.4.33 → 上次交付的 v1.4.34 → 当前 v1.4.35。

## 1. 根因与修复

v1.4.34 的 `app/ui/index.html` 加载 `/ui/biz-workspace.js`，但 `app/main.py` / `app/client_portal.py` 没有该资源对应的路由，实际 HTTP 请求为 404。由此导致思博客户服务左侧五个子页面切换事件从未安装；“调整额度”依赖切换动作，因此也无法显示正确的额度表单。之前离线预览使用内联 JS，不经 HTTP，所以未覆盖该错误。

**新方案**：`app/ui/admin.js` 是五份旧管理员脚本（`ui.js`、`business-admin.js`、`biz-workspace.js`、`self-service-admin.js`、`remote-admin.js`）的统一文件。后端仅提供 `/ui/admin.js` 这个受管理员鉴权保护的路由；后台 `index.html` 加载它一次；JS/CSS 添加 `Cache-Control: no-store` 和 `v=1.4.35` 版本参数。额度快捷按钮会自动切至“公告与额度”、带入选中服务 ID、读取现有额度并定位编辑区。

## 2. 正式包精简

- 根目录原 14 个 `.cmd`（v1.4.34）合并为 **3 个**：`Install-All.cmd`、`Start-VM-Orchestrator.cmd` 和 `Manage.cmd`。
- 管理菜单统一管理员初始化、Guest 网段/防火墙、管理端 ACL、登录自启、密钥导出、依赖修复。
- 删除已无对应入口的旧 Host 检查、Venv 归档脚本、模板生成脚本、手动模板登记脚本（仍可通过后台登记模板）。
- 将 `CHANGELOG.md` 和上一版本审查记录归入 `docs/`；旧版本管理 JavaScript 从五份收敛为一份。
- `Windows10-Template-Tools` 从正式 Host 包中移除，提供**独立 ZIP**；客户机 Guest Agent 分发源、OOBE 运行脚本保留于 Host，兼容现有下载、远程部署和客户注册流程。
- 删除正式发布中的历史测试文件、`__pycache__`、数据库/证书/密钥。升级器只归档“明确已知的历史发行文件”，不清理未知用户文件。

### 正式目录

```text
VM-Orchestrator-v1.4.35/
├─ Install-All.cmd + Install-All.ps1
├─ Start-VM-Orchestrator.cmd
├─ Manage.cmd
├─ README.md / VERSION / requirements.txt

├─ scripts/host/    # Host 启动与管理模块
├─ scripts/guest/   # Guest OOBE、封装及注册模块
└─ docs/            # 版本历史和业务集成说明
```

## 4. 升级与回滚注意事项

1. 在宿主机备份 `D:\VMware\VM-Orchestrator`、客户 VM 及数据（尤其 SQLite / DPAPI）。**先停 8765、8766 老进程**。
2. 新 ZIP 解压在正式安装目录之外，运行 `Install-All.cmd`。安装器备份已有 app/scripts/data，复制新文件，并把明确列出的旧脚本、旧 JS 和模板源码移入 `backup-before-v1.4.35-*`。
3. 启动 `Start-VM-Orchestrator.cmd`（与 VMware Workstation 相同 Windows 用户），后台入口为宿主机 8765。升级后浏览器按 **Ctrl+Shift+R** 强制刷新。
4. 双击 `Manage.cmd` 打开维护菜单；首次管理员初始化可执行 `Manage.cmd account`。
5. Golden Win10 模板使用**单独模板工具 ZIP**，不要在已交付客户 VM 执行 Sysprep。
6. Windows 真机、爱快 ACL、DSM/ESA、思博 API 商品开通/续费、Guest WSS 等需要在备份环境进行最终验收。管理端 8765 严格限受信 IP，Guest 8766 严格限客户网段。

**回滚**：关闭新进程，恢复整套原 app/scripts/data（尤其不要混用新旧数据库结构），再由原版启动脚本起服务；不要复制空库覆盖原客户资料。
