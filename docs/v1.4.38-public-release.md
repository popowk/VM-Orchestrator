# v1.4.38 — 公开仓库发布与自动更新审查

## 已修复

- 允许向已授权的 `popowk/VM-Orchestrator` 公开仓库上传；发布脚本仅暂存明确允许的目录和文件，阻止典型敏感文件路径进入提交。
- 公共 GitHub Releases 使用匿名 API，无需读取 Token；原有私有 Release 的 DPAPI Token 功能保留。
- 更新组件禁止任何未经认可的重定向，跨主机下载时移除 Authorization 标头，避免私有 Token 传递给 Release 存储站点。
- 先将状态置为 `applying` 再启动外部 PowerShell，避免异步更新快速完成时被主服务覆盖成功结果；将 `restarting` 视为忙碌状态，避免更新中误触二次操作。
- 保留原来的 8765/8766 隔离、备份、数据保护和 Windows 回滚流程。

## 发布

在 Windows 机器安装 Git for Windows 和 GitHub CLI，`gh auth login`，再运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\Publish-To-GitHub.ps1 -PublicApproved
```

首次推送会创建 `main` 分支源代码和 `v1.4.38` 标签。GitHub Actions 触发 Release 打包。不要直接上传带运行期数据的 Windows 安装目录。

## 使用和限制

公开 Release 不需要 token；在后台点击「系统更新」→「检查更新」→「一键获取并更新」。版本相同不会自动覆盖。

检查覆盖 Python/JS 语法、Release 打包、远程接口鉴权、GitHub 重定向与更新状态单元测试。Windows 服务停止、依赖安装、数据备份与回滚应先在测试环境验收。
