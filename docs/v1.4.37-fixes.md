# VM Orchestrator v1.4.37 修复与升级说明

基于 **v1.4.36** 修复；不需要更新 Windows 10 黄金模板工具包、Guest Agent 二进制或重建客户 VM。

## 已修复

1. **客户端自助操作按钮**：已选择的操作不再被旧执行记录无说明地置灰。无阻塞时显示「执行操作」并允许点击；如果存在运行中、结果未知或待管理员审核的任务，则显示可点击的「查看执行限制」和具体原因。这个按钮**只展示原因，不会绕过服务器的执行互斥、权限、在线状态与幂等校验**。未开启商品自助操作时会明确提示管理员授权。
2. **非 HTTPS 浏览器兼容**：若 `crypto.randomUUID()` 不可用，则使用 `crypto.getRandomValues()` 生成安全的 UUIDv4；无法提供安全随机数时拒绝操作并给出说明。
3. **最近执行记录**：加入执行时操作名称、中文状态和时间；去掉时间尾部重复的“（北京时间）”，底层时区仍为 Asia/Shanghai；只展示最新 5 条。历史名称会在初次启动自动迁移并回填，之后的操作保存独立快照。已经被删除且无法查询的旧操作显示「已删除的自助操作」。
4. **最近任务**：中文名称与状态分栏展示，客户端 API 最多返回最新 5 条，页面也限定最多 5 条。
5. **客户公告的段落格式**：管理后台输入真实换行、空行或缩进后会按实际格式发布；发布前提供纯文本预览；将 Windows/旧 Mac 换行统一为 LF，保留正文首尾可见换行。客户端使用 `textContent` 与 `white-space: pre-wrap` 显示，不执行 HTML。

## 执行安全

如果客户点击后显示「查看执行限制」，请在管理后台「思博客户服务 → 客户自助 → 执行记录」核对旧任务。对于结果不明的执行，只有管理员检查 Guest 进程/更新日志并确认后才允许解除限制。**不要手动删库、强制将 RUNNING 改成 SUCCEEDED，或让同一 VM 并发执行两条有副作用的操作。**

历史记录展示最新 5 条，不影响后台检查所有旧执行记录是否仍存在阻塞。该逻辑经过旧版 SQLite 迁移与安全测试。

## 升级

1. **先备份** `D:\VMware\VM-Orchestrator` 整个目录，尤其 `data/`、证书与 DPAPI 密钥。
2. 停止当前 8765/8766 两个监听，确保没有旧 Python 进程继续写入 SQLite。
3. 将 ZIP 解压到独立文件夹，运行 `Install-All.cmd`；安装脚本会备份旧 `app/`、`scripts/` 和 `data/` 后再复制新版运行代码。
4. 启动 `Start-VM-Orchestrator.cmd`，在管理后台刷新，客户端使用 **Ctrl+Shift+R** 刷新页面，确认 `/ui/client.js?v=1.4.37` 成功加载。
5. 用一个可丢弃的测试客户实例核对：自助操作可点、阻塞时正确提示、客户历史最多 5 条、公告连续换行展示。确认后再用于生产订单。

## 验证范围与限制

- Python 全模块编译、`admin.js`/`client.js` JavaScript 语法检查通过。
- 独立 SQLite 测试通过：公告多行保存与确认、历史表迁移、最新 5 条、超出最近列表的旧阻塞依然有效、管理员确认解锁、历史操作名称保留。
- Chromium 隔离页面交互通过：操作下拉选中、真实按钮提交、旧任务拦截、状态解除、公告纯文本多行展示、两组 5 条记录渲染。
- **未在实际 Windows VMware 宿主机、Guest WSS、思博真实订单环境做端到端测试**；重要业务需在测试客户 VM 回归。
