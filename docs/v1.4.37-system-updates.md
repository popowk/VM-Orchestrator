# VM Orchestrator v1.4.37 — GitHub Releases 系统更新

## 实现范围

- 管理后台独立「系统更新」工作区，与 Guest 软件更新分离。
- `GET /api/system/update?check=true` 验证 Release 是否存在；`POST /api/system/update/apply` 提交管理员确认后自动下载、校验、备份与重启。
- GitHub API 仓库固定为 `owner/name`（默认 `popowk/VM-Orchestrator`）；私有仓库令牌由 `Manage.cmd github` 写入当前 Windows 用户 DPAPI。
- 只接受正式 Release 中同版本的 `VM-Orchestrator-vX.Y.Z.zip` 与 `VM-Orchestrator-vX.Y.Z.zip.sha256`。哈希不匹配立即拒绝安装。SHA256 是完整性验证，不代替 Release 发布权限控制或独立数字签名。
- 独立 PowerShell 更新器在停止统一 Host 进程后替换程序；保留 `data`、DPAPI 密钥、配置、客户 VM 和模板目录。失败自动从版本化程序备份中恢复旧版。
- 默认没有运行中 VM 管理任务才允许更新。为避免影响客户业务，请选维护窗口执行。

## GitHub 私有仓库发布

1. 通过 GitHub 网页新建 `popowk/VM-Orchestrator` 并选 **Private**，不要推送到公开的无关仓库。
2. Windows 上准备 Git for Windows 与 GitHub CLI，运行 `gh auth login`；再运行 `powershell -ExecutionPolicy Bypass -File .\tools\Publish-To-GitHub.ps1` 自动新建私有仓库并推送，或手动用 Git 上传。
3. Actions 有 `contents: write` 权限。创建 `v1.4.37` 标签并 `git push origin v1.4.37`，Actions 工作流会生成 GitHub Release ZIP + SHA256。
4. 后续变更必须同步修改 `VERSION`，通过完整回归后创建更高版本标签（如 `v1.4.38`），管理后台才会显示可升级。

## 安装后配置

在宿主机运行 `Manage.cmd` → **10. Configure GitHub private release update source**。在 GitHub 的 Settings / Developer settings / Personal access tokens (fine-grained) 创建仅授权新仓库、仅 Contents 读取权限的 token。令牌不要复制进聊天、Github Actions 日志或仓库。重启服务后在管理后台「系统更新」中检查，首次版本相同会显示“已是最新”。

## 更新处理和回滚

1. 后端校验管理员会话及 CSRF，并检查没有排队或运行中的 VM 任务。
2. 读取 GitHub latest Release；验证标签、文件名、大小上限和 sha256 清单；下载 ZIP 后校验哈希、版本和目录结构。
3. 启动独立 Windows PowerShell 5.1 进程。它再次校验哈希，解压审查之后停掉旧统一服务。
4. 备份当前 `app/`、`guest_agent/`、`scripts/`、`integrations/`、`docs/` 和根目录运行文件至 `data/updates/backups/`。不更改 `data/`、外部数据库、客户虚拟机以及模板文件。
5. 部署新版本、验证依赖、重启，等候带 `version` 字段的 `/health` 返回匹配版本。失败则恢复程序备份并尝试重新启动旧版。
6. 日志：`data/updates/updater.log`；状态：`data/updates/status.json`；需人工排障时可从 `data/updates/backups/` 取回旧文件。

## 安全与限制

- 尚未在真实 Windows/VMware Workstation 环境完整验收；先用非生产环境测试下载、升级、备份、回滚和服务恢复。
- SHA256 清单与 ZIP 同属 GitHub Release，依赖私有仓库管理员及 GitHub 权限的可信度；需要更高安全级别可加入离线 Ed25519 签名验证。
- 自动更新会中断 Host 统一进程，可能影响正在进行的客户远程管理或流式会话；需维护窗口更新。
- 登录管理员也必须明确点击并确认更新；没有无人值守自动安装计划。
- 程序备份不等于客户数据备份；更新前请另行备份数据库及 Windows 目录。
- 不会从其他仓库下载、不接受任意 URL 或不匹配版本号的包。
- **本源码包尚未上传 GitHub**：当前连接的账号没有目标私有仓库；创建后再执行推送。
